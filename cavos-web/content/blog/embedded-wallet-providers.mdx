## What an embedded wallet (and wallet-as-a-service) is

The user signs in the way they already do. The SDK looks up or creates an on-chain account for that identity. Approval stays in the product. There is no seed phrase in the happy path and no second program to install.

That is **where the wallet appears**. It is not a custody claim. An embedded wallet can be device-native self-custody, MPC shares, a remote enclave, or a delegated TEE. A wallet-as-a-service API can sit at any of those layers. Turnkey is closer to signing infrastructure. Privy, Dynamic, Magic, Web3Auth, and Cavos ship a finished login-to-signature path. Ask who can move funds without the user present. The [custody](/custody) page is the control test; this page is the shortlist.

## How to evaluate providers

Write the answers down before you read a pricing page. **Best embedded wallet providers 2026** is this checklist, not a logo ranking. The [embedded wallet](/embedded-wallet) pillar is the product definition; this page is the named-vendor table. Replacement shortlists: [Privy alternatives](/privy-alternatives), [Turnkey alternatives](/turnkey-alternatives), [Dynamic alternatives](/dynamic-alternatives), [Magic alternatives](/magic-alternatives), [Web3Auth alternatives](/web3auth-alternatives), [Dfns alternatives](/dfns-alternatives), [Para alternatives](/para-alternatives).

- **Custody / key model.** Device-native, MPC, TEE or HSM, remote enclave. Who holds a share, a wrap, or a credential that can authorize a spend. Ask who can produce a valid signature without the user present. Embedded is a UX label; [non-custodial embedded wallets](/blog/non-custodial-embedded-wallet) is the control test.
- **Chains.** Which networks are native (account model, fees, signatures) versus a reused EOA-shaped key versus a sign-only curve. Cavos is [Starknet](/embedded-starknet-wallet), [Solana](/embedded-solana-wallet), and [Stellar](/embedded-stellar-wallet) only. A long named list is not the same as a native adapter on the chain you ship.
- **Enclave vs MPC.** Shamir reconstruct in a vendor TEE (Privy user wallets), keys that decrypt only in a vendor enclave (Turnkey), TSS/MPC ceremonies that never reconstruct a key (Dynamic, Dfns, Para, Web3Auth TSS path), or a key that never leaves the device in plaintext (Cavos). Those are different incident and export stories.
- **Pricing transparency.** Units differ: wallet creates, monthly active users, monthly active wallets, signatures, volume. Write down the meter, the free-tier cap, overage, and which features are sales-gated. A cheap free tier with a tight MAU cap is not the same as a flat wallet-create allowance. Worked cost at 10k / 100k / 1M users is [how much embedded wallets cost](/blog/embedded-wallet-cost).
- **Gas sponsorship.** Whether first transactions work with an empty native-token balance, and whether that feature is on the public plan or enterprise-only.
- **Auth methods.** Email, social, SMS, passkeys, bring-your-own JWT. Login selects the user. It should not, by itself, be the spend key, unless you chose a hosted model on purpose.
- **Lock-in.** Can the user export a key? Can you restore the same address on another vendor? Addresses are derived differently. Migration is a project. Confirm export, import, and what happens if you cancel the subscription.

## Comparison criteria: custody, chains, pricing, enclave vs MPC

The table above is the shortlist. This section is how to read it.

**Custody.** Device-native means the spend key is created and used on the user’s device; the provider cannot see it, sign with it, or decrypt it. Cavos is this model. Shamir-in-a-TEE means shares combine inside a vendor enclave after authentication (Privy user wallets). Enclave-credential means plaintext exists only inside a TEE the vendor operates, and custody is who can authorize that TEE (Turnkey). TSS/MPC means shares jointly produce a signature and a complete private key is not supposed to exist (Dynamic, Para, Dfns, Web3Auth). Optional licensed-custodian paths (Privy + Bridge) are a separate product, even when they share a dashboard.

**Chains.** Count native account models, not logos. Managed send, sign-transaction, sign-only, curve-level signing, and a named Tier 1 row are different depths. Confirm the current vendor page before you promise a network. Chain-specific shortlists: [best embedded wallets for Stellar](/blog/best-embedded-wallets-stellar), [Solana](/blog/best-embedded-wallets-solana), and [Starknet](/blog/best-embedded-wallets-starknet).

**Pricing transparency.** Ask what the invoice meters, what the free tier includes, what overage costs, and which features are Enterprise-only. Where two public sources disagree (Dynamic extra-MAU) or a rate is sales-gated, write “unpublished” instead of guessing. Cavos publishes wallet-create plans on [pricing](/pricing): free for the first 1,000, Essential $59/mo, Complete $139/mo.

**Enclave vs MPC vs device.** A vendor TEE that reconstructs or decrypts a key, an MPC ceremony that never reconstructs, and a device-native key are three architectures. They are not marketing synonyms. Finished SDK versus signing infrastructure is [Privy vs Turnkey](/blog/privy-vs-turnkey). The commercial label is [wallet-as-a-service](/blog/wallet-as-a-service).

**Web3Auth / MetaMask Embedded Wallets** is chain-agnostic MPC. Official docs describe threshold signatures and Shamir’s Secret Sharing, native EVM and Solana providers, and connect guides for other networks including Cosmos, Sui, and Starknet. The product page lists SOC 2 Type II and a 99.9%+ uptime claim. Pricing is monthly active wallets: free 1,000 MAWs, Growth $69/mo, Scale $399/mo.

**Dynamic** is a unified login and wallet-connection layer that also ships TSS-MPC embedded wallets. Connecting wallets users already hold is core. The JS/React Tier 1 send-and-sign table is the longest named native list in this shortlist, including Stellar, Sui, Aleo, and Midnight. Starknet is not on that Tier 1 table. Growth is $249/mo for up to 5,000 MAUs. Gasless EVM and Solana are listed as Enterprise.

Pick Web3Auth when social login, MetaMask-branded infrastructure, and a chain-agnostic MPC stance match the review. Pick Dynamic when connectors plus that named native list are the job. Neither is a device-native Starknet, Solana, and Stellar adapter. The one-to-one pages are [Web3Auth vs Cavos](/compare/web3auth) and [Dynamic vs Cavos](/compare/dynamic). The two-way with Privy is [Privy vs Dynamic](/blog/privy-vs-dynamic).

## How do Para and Dynamic embedded wallets compare?

**Para** (getpara.com, not ParaSwap) documents 2-of-2 MPC, a named chain-support table of EVM, Solana, Cosmos chains (Noble, Initia, Osmosis), and Stellar, and MAU-only pricing: free to 1,200 MAUs, then $200 / $500 / $1,000 per month. The public pricing FAQ lists SOC 2 Type II and says Para does not charge per signature. Sui appears in the chain-support intro, not as a named table row.

**Dynamic** is stronger when connecting wallets users already hold is first-class, or when you want JS/React Tier 1 native send-and-sign on a list that also names Aleo and Midnight. Para is stronger when you want that shorter named table, MAU-only billing, and a public SOC 2 Type II claim on the pricing page.

The replacement shortlist for getpara.com is [Para alternatives](/para-alternatives). Dynamic’s is [Dynamic alternatives](/dynamic-alternatives).

## What an enterprise should evaluate

Embedded is a UX label. An enterprise review still has to answer who can sign, what was audited, and what the invoice meters. The [custody](/custody) page is the control test. Pricing transparency at 10k / 100k / 1M users is [how much embedded wallets cost](/blog/embedded-wallet-cost).

- **Custody model.** Device-native (Cavos), Shamir reconstruct in a TEE (Privy user wallets), TSS-MPC (Dynamic, Web3Auth TSS path, Para), keys that decrypt only in a vendor enclave (Turnkey). Who can produce a valid signature without the user present.
- **Key export.** Privy user wallets document export. Dynamic documents export. Turnkey lists import and export keys. Web3Auth describes export as part of the MPC model. Cavos restores the MasterDEK on a new device and does not advertise seed or private-key export.
- **SOC 2 and audits, as published.** MetaMask Embedded Wallets lists SOC 2 Type II on the product page. Para’s pricing FAQ lists SOC 2 Type II. Cavos does not publish a SOC 2 report on this site. The Starknet account is an **audited OpenZeppelin account contract**; the audit covers OpenZeppelin’s contract, not Cavos. Do not treat an account-contract audit as a vendor SOC 2.
- **Pricing transparency.** What the invoice meters, what the free tier includes, what overage costs, and which features are Enterprise-only. Where two public sources disagree (Dynamic extra-MAU) or a rate is sales-gated, write “unpublished” instead of guessing.
- **SLAs.** Privy, Dynamic, Turnkey, and MetaMask Embedded Wallets list SLAs on Enterprise. Cavos does not publish an uptime SLA on [pricing](/pricing).

## Privy vs Turnkey vs Dynamic

Treat this as a scope question, not a feature checklist.

**Privy** is a finished embedded wallet and authentication product. The public pricing page lists unified login (email, SMS, socials, passkeys), [embedded wallets](/embedded-wallet), and wallet connectors for EVM and Solana. Keys are managed in Privy’s TEE infrastructure. Privy’s own docs say neither Privy nor the application sees the user’s keys on the non-custodial path; secrets are reconstituted in a secure environment under the user’s control. In 2026 Privy also added optional custodial wallets, starting with Bridge, chosen per wallet. Use Privy when you want one vendor for login, an in-app wallet, and connecting wallets users already hold, especially on EVM.

**Turnkey** is key-management infrastructure. Private keys persist as ciphertext and decrypt only inside AWS Nitro Enclaves. Custody is determined by who holds the credentials that can authorize the enclave: the end user (non-custodial), your API key (custodial), or both under policy (hybrid). Auth includes passkeys, OAuth, email, and API keys. Gas sponsorship is listed on the Enterprise plan. Use Turnkey when you are building a wallet or custody product and want policy, quorums, and server-side signing primitives. Privy vs Turnkey is usually build-versus-buy.

**Dynamic** is strongest as a unified login and wallet-connection layer that also ships [embedded wallets](/embedded-wallet). Connecting existing external wallets is a core capability. Embedded wallets use TSS-MPC: a user share on the device and a server share that participates in signing inside a TEE. Dynamic’s public docs say the full private key is never constructed, wallets are end-user owned, and export is supported. Native Tier 1 embedded-wallet chains on the public JS/React docs include EVM, Solana, Bitcoin, Sui, Tempo, Arc, TON, Stellar, Tron, Aleo, and Midnight. Gasless transactions on EVM and Solana are listed as an Enterprise feature. Use Dynamic when users already hold wallets you must connect, or when you want that connector surface plus an embedded fallback. Privy vs Dynamic is usually provision-versus-connect.

None of those three is “the Starknet / Solana / Stellar device-native SDK.” That is a different product shape.

## When Cavos is the right pick, and when it is not

Cavos is a hardware-isolated, non-custodial [embedded wallet](/embedded-wallet), not an extension, and not a connector.

Signing keys are created and used on the user’s device. Keys never leave the device in plaintext. Signing always happens on the device. Cavos cannot see them, sign with them, decrypt them, or move funds. Login produces a stable identity for a registry lookup; it never signs a transaction. There is no MPC. There is no hosted spend key.

On Starknet the on-chain account is an **audited OpenZeppelin AccountUpgradeable** v3.0.0, controlled by one stark key derived from the wallet’s MasterDEK and app salt. The audit covers OpenZeppelin’s contract, not Cavos. Cavos does not ship its own account implementation. There is no on-chain device-signer list and no on-chain social recovery. A new device restores the MasterDEK off-chain with a passkey or an opt-in AWS Nitro Enclave. The passkey and the enclave only hold an encrypted copy of the MasterDEK for sealed restore; they cannot sign, and Cavos cannot decrypt that copy. A new device does not `add_signer`. Execution is paymaster-sponsored. Connect does not deploy, the first execute deploys and runs atomically.

Solana and Stellar are native adapters, not EVM compatibility. Solana provisions a native Ed25519 system account; a relayer co-signs as fee payer. Stellar provisions a classic G… account so existing tools already understand the address; the relayer can sponsor reserves and fee-bumps. Both restore the same MasterDEK on a new device rather than adding a second on-chain signer.

Auth is hosted Google, Apple, or email, or an identity you pass in from your own stack. The React path is `@cavos/kit`; mobile (`@cavos/kit/react-native`) is a work in progress. The current kit release is [Cavos Kit 0.5.0](/blog/cavos-kit-0-5-0). The [React integration guide](/blog/how-to-add-an-embedded-wallet) and the [Cavos docs](https://docs.cavos.xyz/docs/quickstart) are the install. [Pricing](/pricing) publishes the free 1,000 wallet creates, Essential at $59/mo, and Complete at $139/mo with enclave recovery.

**Choose Cavos** when the user should never see a wallet picker, the chain is Starknet, Solana, or Stellar, and the review requires that the vendor cannot reconstruct a signing key.

**Choose someone else** when the product is EVM-first, when you must connect MetaMask or WalletConnect, when you need server-side signing or organizational quorums as a product feature, or when you want a single vendor across dozens of EVM networks. Cavos does not inject into `window.ethereum` and does not speak WalletConnect. Those are honest gaps, not a smaller feature set.
