`@cavos/kit` gives applications one [embedded wallet](https://cavos.xyz/embedded-wallet)
integration across chains without flattening their differences. Users
authenticate with a familiar identity and control a deterministic wallet
through device-native key material, no seed phrase, MPC cluster, or browser
extension.

**[Starknet](https://cavos.xyz/embedded-starknet-wallet),
[Solana](https://cavos.xyz/embedded-solana-wallet), and
[Stellar](https://cavos.xyz/embedded-stellar-wallet) are available today.**
Cavos is designed to reach every chain through adapters that preserve the same
product contract while using each network's native account, signing, execution,
and fee model.

```ts title="TypeScript"
import { Cavos } from "@cavos/kit";

const wallet = await Cavos.connect({
  chains: ["solana"], // any of "starknet" | "solana" | "stellar"
  network: "testnet",
  identity: { userId: user.id, email: user.email },
  appSalt: "my-app",
  appId: process.env.NEXT_PUBLIC_CAVOS_APP_ID,
});

if (wallet.chain === "solana" && wallet.status === "ready") {
  // Moves 0.001 SOL the account holds; the Cavos relayer pays the fee.
  await wallet.execute(1_000_000n, recipient, { fee: "sponsored" });
}
```

## The stable product contract

| Piece | Role |
|---|---|
| **Identity** | A stable `userId` plus an app-specific salt. On every chain the salt is also HKDF input for the account key. |
| **Device-native authority** | Every account key is derived from a MasterDEK: a stark key on Starknet, native Ed25519 on Solana and Stellar. |
| **Chain adapter** | Implements address derivation, signing, execution, recovery, and sponsorship for one network family. |
| **Unified SDK** | `Cavos.connect({ chains, network })` returns a discriminated wallet union so shared onboarding stays stable and chain-native methods remain typed. |
| **Sponsorship** | A paymaster, relayer, fee payer, or fee-bump service removes the need for users to acquire gas when that adapter supports it. |

## What remains chain-native

Execution is intentionally not reduced to a misleading universal transaction
format:

- **Starknet:** standard OpenZeppelin account, arbitrary multicalls, Starknet paymaster.
- **Solana:** native Ed25519 system account, transfer or allowlisted instructions; the account, the Cavos relayer, or a held token pays the fee.
- **Stellar:** classic `G…` account, native Ed25519 control key (derived from the MasterDEK), XLM payments, Soroban invocation, optional fee-bump.

Narrow on `wallet.chain` before calling chain-native methods. See
[Chains](/docs/chains) for the capability matrix.

## Security properties

- **Self-custodial:** private keys never leave the user's device in plaintext and are never used to sign on a server. The enclave and passkeys hold only an encrypted copy of the wallet's master key.
- **MPC-free:** there are no reconstructable server-side key shards.
- **Device-native:** authority is created or unlocked locally on an enrolled
  device.
- **Deterministic identity:** the same stable identity and app salt resolve to
  the same wallet for that adapter.
- **Recoverable:** each adapter exposes non-custodial device approval and
  recovery appropriate to its account model.
