Solana in `@cavos/kit` is a **native system account**. The address is an
Ed25519 public key — the same shape as Phantom — not a PDA and not a P-256
program account.

The spend key is HKDF of a **MasterDEK** (`cavos-ed25519-solana-v1`, salted by
`appSalt`). The same DEK derives the Stellar `G…` in a multi-chain enclave
session. A new device restores that DEK with the [enclave](/docs/hardware-isolated-recovery)
or a [passkey PRF](/docs/passkeys). Login never asks for a passkey.

The Cavos relayer co-signs as **fee payer only**. It cannot spend. The user still
needs SOL in the account to transfer; sponsorship covers the fee, not the
balance.

## Connect

Use `Cavos.connect` with `chains: ["solana"]`. An `appId` activates the relayer.
Connect resolves the address and unwraps the spend key on this device. It does
**not** airdrop SOL and there is no `initialize` instruction.

```ts title="TypeScript"
import { Cavos } from "@cavos/kit";

const session = await Cavos.connect({
  chains: ["solana"],
  defaultChain: "solana",
  network: "testnet",                   // "testnet" (devnet) | "mainnet"
  appSalt: "my-app",                    // HKDF salt — never change it
  identity: {
    userId: user.id,
    email: user.email,
  },
  appId: process.env.NEXT_PUBLIC_CAVOS_APP_ID,
});

const wallet = session.wallet("solana");
console.log(wallet.address);            // base58 Ed25519 system account
console.log(wallet.status);             // "ready" | "needs-device-approval"
```

`network: "testnet"` resolves to `solana-devnet`; `"mainnet"` resolves to
`solana-mainnet`. Narrow on `wallet.chain` before chain-native calls.

<Callout type="warn">
**Pass your own RPC on mainnet.** Without `rpcUrl` / `rpcUrls.solana`, the kit
falls back to public `api.mainnet-beta.solana.com`, which is rate-limited.
Provide Helius / Triton / QuickNode in production.
</Callout>

## Status values

| Status | Meaning | Can execute? |
|--------|---------|--------------|
| `ready` | This device unwrapped the Ed25519 spend key | Yes — if the account holds lamports |
| `needs-device-approval` | Registry has an address, this device has no wrap | No — restore with enclave login or `approveDeviceWithPasskey()` |

Native Solana does not use `undeployed` the way Starknet does. There is nothing
to deploy: a system account appears when it first receives lamports. After
connect, `isDeployed` is `true` once the spend key is present.

<Callout type="info">
**Fund the address, then spend.** The relayer pays fees on `execute`. It does
not put SOL in the user account. Send devnet SOL to `wallet.address` (or use a
faucet) before the first transfer.
</Callout>

## Execute a transfer

`execute(amount, destination)` moves `amount` **lamports** from this system
account. The user's Ed25519 key signs the Solana message; the relayer is fee
payer.

```ts title="TypeScript"
if (wallet.chain === "solana" && wallet.status !== "needs-device-approval") {
  const signature = await wallet.execute(
    1_000_000n,                          // 0.001 SOL, in lamports
    recipientPublicKey,                  // base58
  );
  console.log(signature);
}
```

`amount` is a `bigint` of lamports (`1 SOL = 1_000_000_000 lamports`).

## Execute arbitrary instructions

`executeInstructions` submits the user's signed transaction. The account is a
normal signer (owner of ATAs, etc.), not a PDA that CPIs on the user's behalf.

```ts title="TypeScript"
import { createTransferInstruction, getAssociatedTokenAddress } from "@solana/spl-token";
import type { InstructionData } from "@cavos/kit";

const source = await getAssociatedTokenAddress(usdcMint, new PublicKey(wallet.address));
const dest = await getAssociatedTokenAddress(usdcMint, recipientPublicKey);
const ix = createTransferInstruction(source, dest, new PublicKey(wallet.address), amount);

const instructions: InstructionData[] = [{
  programId: ix.programId.toBase58(),
  accounts: ix.keys.map((k) => ({
    pubkey: k.pubkey.toBase58(),
    isSigner: k.isSigner,
    isWritable: k.isWritable,
  })),
  data: ix.data,
}];

if (wallet.chain === "solana" && wallet.status !== "needs-device-approval") {
  await wallet.executeInstructions(instructions);
}
```

<Callout type="warn">
**Sponsorship is allowlisted.** The relayer only co-signs instructions whose
program ids are in the app's **Solana program allowlist** (dashboard → Solana
Programs) **plus** System, SPL Token, Token-2022, and Associated Token. A
1,000,000 CU cap also applies.
</Callout>

`addSigner`, `removeSigner`, `enrollPasskey` (as an on-chain approver), and
`CavosSolana.recover` **throw**. `setupRecovery` is a **no-op**. A native
account has one spend key. Restore it; do not add a second signer.

## Sign messages

```ts title="TypeScript"
const sig = await wallet.signMessage("Hello, Cavos!");
// sig.signature: Uint8Array (ed25519)
// sig.publicKey: base58 address
// sig.curve: "ed25519"
```

## How keys work

1. First device mints a random MasterDEK (or derives it from passkey PRF).
2. Solana seed = HKDF-SHA256(DEK, appSalt, `"cavos-ed25519-solana-v1"`).
3. Address = Ed25519 public key of that seed. Registry claims
   `(userId, appId, chain, network)`.
4. Local wrap of the DEK lives in IndexedDB (`cavos-kit-dek-wrap`), keyed by
   `userId`. The enclave also seals it when `deviceApproval: "enclave"`.
5. A reconnect that already has the local wrap **reseals** the enclave so a
   phone can recover even if the first enroll failed.

`appSalt` is part of the HKDF. Changing it derives a different address that will
not match the registry row.

## Gasless vs self-funded

| Path | When | Who pays the fee |
|------|------|------------------|
| **Relayer (default)** | `appId` is set | Cavos relayer as fee payer |
| **Self-funded** | `feePayer` Keypair, `{ sponsored: false }` | Your keypair |

The relayer never becomes the source of a user transfer.

## Networks

```ts title="TypeScript"
import { SOLANA_NETWORKS } from "@cavos/kit";

SOLANA_NETWORKS["solana-devnet"];   // https://api.devnet.solana.com
```

There is no `DEVICE_ACCOUNT_PROGRAM_ID` and no `SolanaAdapter` in this release.

## Recovery

| Path | What happens |
|------|----------------|
| **Enclave** | Sign in again. The enclave unwraps the MasterDEK onto this device. |
| **Passkey** | `approveDeviceWithPasskey()` → `connect({ passkey: true })`. PRF is the KDF. |
| **Recovery code** | Not used. `setupRecovery` is a no-op; `CavosSolana.recover` throws. |

See [Hardware-isolated recovery](/docs/hardware-isolated-recovery) and
[Passkeys](/docs/passkeys). Login never prompts for the passkey.

## What's available

- ✅ Native Ed25519 system account.
- ✅ Relayer as fee payer.
- ✅ `execute` / `executeInstructions` signed by the user key.
- ✅ `signMessage` with `curve: "ed25519"`.
- ✅ Enclave DEK wrap and passkey PRF restore.
- ❌ PDA, secp256r1 precompile program, on-chain approvers, `addSigner`.
