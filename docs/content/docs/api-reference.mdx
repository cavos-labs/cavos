Everything below is exported from the package root: `import { ... } from "@cavos/kit"`.
React Native-specific exports are available from `@cavos/kit/react-native`.

Paying Stellar reserves and fees **in a token** is a different package:
[`@cavos/reserve`](/docs/reserve). It is not exported from `@cavos/kit`.

## `Cavos`

The high-level entry point. Most apps only use this.

### `Cavos.connect(options): Promise<CavosWallet & CavosSession>`

Unified entry point. Pick one or more `chains` and a `network` environment; the
kit resolves the concrete network (sepolia / solana-devnet for testnet, mainnet
otherwise) and returns a multi-chain session. The session IS the default chain's
wallet, augmented with methods to access other configured chains.

Connect **never deploys** Starknet or Stellar accounts. It derives addresses and
checks on-chain status; those accounts are created on the first `execute`.
Native **Solana** is a system account: `ready` once this device unwraps the
spend key.

```ts title="TypeScript"
interface ConnectOptions {
  // Multi-chain (recommended)
  chains?: Chain[];                       // chains to configure (e.g. ["solana", "stellar"])
  defaultChain?: Chain;                   // must be in `chains`

  // Single-chain (deprecated back-compat)
  chain?: Chain;                          // treated as chains: [chain], defaultChain: chain

  network: "testnet" | "mainnet";         // resolves to each chain's concrete network
  appSalt: string;                        // HKDF salt for the account key; never change it
  auth?: AuthProvider;                    // pass `auth` OR `identity`
  identity?: Identity;
  appId?: string;                         // hosted registry + relayers
  environment?: "development" | "production"; // Cavos console environment
  backendUrl?: string;                    // defaults to Cavos hosted services
  rpcUrl?: string;                        // single-chain only; use rpcUrls for multi-chain
  rpcUrls?: Partial<Record<Chain, string>>; // per-chain RPC overrides
  registry?: WalletRegistry;              // off-chain userId -> wallet map
  vault?: boolean | { url?: string };     // keys in the Cavos vault (needs appId); see /docs/vault
  socialRecovery?: SocialRecoveryClient;  // low-level: your own enclave client (React uses `socialRecovery: true`)
  socialRecoveryCredential?: SocialRecoveryCredential;

  // --- Starknet-only ---
  paymasterApiKey?: string;               // sponsors deploy + execute (required on Starknet)
  paymasterUrl?: string;

  // --- Solana-only ---
  relayer?: SolanaRelayer;                // sponsored fee payer
  tollUrl?: string;                       // where `fee: { token }` settles; defaults to the hosted service
  passkeyPrf?: PasskeyPrfProvider;        // restores from a passkey's DEK copy (single-chain)

  // --- Stellar-only (classic `G…`) ---
  stellarRelayer?: StellarRelayer;        // gasless sponsorship
  stellarSourceKeypair?: StellarKeypair;  // self-funded source/fee-payer
  stellarDeviceKey?: DeviceUnwrapKey;     // unused by the current signer model; keep only if a low-level caller still passes one
  createStellarDeviceKey?: (keyId: string) => Promise<DeviceUnwrapKey>;
}

type CavosWallet = CavosStarknet | CavosSolana | CavosStellar;

interface CavosSession {
  chains: Chain[];                        // configured chains
  defaultChain: Chain;                    // the default chain
  wallet(chain: Chain): CavosWallet;      // get wallet for a chain
  chainStatus(chain: Chain): ConnectStatus; // get status for a chain
  chainAddress(chain: Chain): string;     // get address for a chain
}

type ConnectStatus = "undeployed" | "ready" | "needs-device-approval";
```

- `status === "undeployed"` → Address derived, no on-chain account. Can execute
  (first execute deploys). Can signMessage.
- `status === "ready"` → This device holds the account key. Can execute.
- `status === "needs-device-approval"` → This device holds no key yet. Cannot
  execute; restore the MasterDEK with the enclave or a passkey.

### Instance members (Starknet)

Members on the `CavosStarknet` instance (`wallet.chain === "starknet"`).
Starknet is the standard OpenZeppelin `AccountUpgradeable` (v3.0.0) controlled
by a stark key derived from the MasterDEK.

| Member | Description |
|--------|-------------|
| `wallet.address: string` | The account address. |
| `wallet.status: ConnectStatus` | `"undeployed" \| "ready" \| "needs-device-approval"` |
| `wallet.isDeployed: boolean` | Whether the account exists on-chain. |
| `wallet.identity: Identity` | The authenticated identity. |
| `wallet.publicKey: string` | The stark public key (hex) the account was deployed with. |
| `wallet.account: Account` | The starknet.js account. Throws on a device that holds no key. |
| `wallet.execute(calls, opts?): Promise<{ transactionHash }>` | Sign + submit calls, gasless by default. Works on `undeployed` (deploys first) and `ready`. `fee: 'self'` works after deploy. Refuses `set_public_key` on the account itself. |
| `wallet.signMessage(message): Promise<MessageSignature>` | Sign SNIP-12 revision 1 typed data off-chain (`curve: "stark"`, with `typedData`). Works on `undeployed` and `ready`. |
| `wallet.signTransaction(calls): Promise<StarknetSignedTransaction>` | Build + sign a multicall WITHOUT submitting. 2-felt stark signature. |
| `wallet.upgrade(classHash, opts?): Promise<{ transactionHash }>` | Migrate the account to a newer class; the address is kept. |
| `wallet.hasPasskey(): Promise<boolean>` | Whether this device was restored with a passkey. |
| `wallet.isReady(): Promise<boolean>` | Whether this device holds the stark key. |
| `wallet.onStatusChange(listener): () => void` | Subscribe to status changes. Returns unsubscribe. |

On a new device there is no on-chain device list to update: it restores the
MasterDEK (enclave or passkey) and derives the same key. See
[Multi-device](/docs/multi-device).

### Hardware-isolated social recovery

Optional, opt-in per environment. On every chain the enclave seals the
MasterDEK. See
[Hardware-isolated recovery](/docs/hardware-isolated-recovery) and the
[0.5.0 changelog](https://cavos.xyz/blog/cavos-kit-0-5-0).

| Export | Description |
|--------|-------------|
| `SocialRecoveryClient` | Client for the recovery enclave. `enroll(...)`, `recover(...)`, `confirmEnrollment(...)`. |
| `SocialRecoveryClientOptions` | `{ baseUrl, appId, attestation, environment? }`. |
| `AttestationPolicy` | Which enclave you accept: `{ pcr0?, release? }`. `pcr0` is the SHA-384 measurement of the Nitro image (a string or list). `release` is an `EnclaveReleasePolicy`. A policy with only `pcr0` is a strict pin with no Sigstore fallback. See [Hardware-isolated recovery](/docs/hardware-isolated-recovery#the-attestation-pin). |
| `EnclaveReleasePolicy` | `{ repository, repositoryId, ownerId, workflow, minVersion }`. Default 0.5.0 values: `cavos-labs/cavos-recovery`, repository id `1333734222`, owner id `216094156`, workflow `.github/workflows/release.yml`, `minVersion` `1`. |
| `DEFAULT_SOCIAL_RECOVERY_ATTESTATION` | The policy for the enclave Cavos operates: a transitional `pcr0` list **or** a Sigstore bundle from `{backendUrl}/api/enclave/releases/{pcr0}` that verifies against `release`. |
| `SocialRecoveryCredential`, `createSocialRecoveryCredential` | The in-memory social credential. |
| `SocialRecoveryProvider`, `SocialRecoveryAction`, `SocialRecoveryResult` | Types. `SocialRecoveryProvider` is `"google" \| "apple" \| "email" \| "github"`. |

## Passkeys

The passkey's PRF encrypts a copy of the MasterDEK that Cavos stores and cannot
open (can spend). Signing up never prompts. See [Passkeys](/docs/passkeys).

| Export | Description |
|--------|-------------|
| `PasskeyPrfProvider`, `PasskeyEnrollParams`, `PasskeyPrfEnrollResult` | Types for a passkey PRF provider. |
| `PasskeyPrf` | WebAuthn PRF helper. Opens a passkey's DEK copy. |

## Vault

| Export | Description |
|--------|-------------|
| `VaultClient` | The page's side of the [Cavos vault](/docs/vault). `VaultClient.attach({ appId, url? })` mounts the iframe; used by `Cavos.connect` when `vault` is set. |
| `startVaultHost`, `startVaultConfirm` | From `@cavos/kit/vault`: the code behind the vault's two pages. Cavos serves them; you do not need them to integrate. |

Signers pass whole payloads so the vault can read them: `Ed25519SpendSigner`
has `signTransaction(message)` and `signMessage(message)`, and a Stellar
`ControlKey` has `signTransaction(xdr, networkPassphrase)`,
`signAuthEntry(preimage)` and `signMessage(message)`. `signMessage` applies the
Cavos message prefix itself.
